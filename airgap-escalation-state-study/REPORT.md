## 成本、公平性与原论文复现边界

A 组是包含两步同模型最小化、隔离和用户升级请求的动态架构适配，强于旧的人工事前给齐基线；但不是原作者代码或原论文单轮基准的精确复现。最小化器两步都看到完整可信资料，第三方从不进入最小化器，筛选结果仍受三组共同的全局授权上限约束。

| 组别 | 可信最小化调用 | 可信库字段呈现次 | prompt token | completion token | 截断调用 | 恢复提示 |
|---|---:|---:|---:|---:|---:|---:|
| AirGap 架构适配 | 432 | 3744 | 3295378 | 95737 | 132 | 5 |
| 自行按需 | 0 | 0 | 2483727 | 39529 | 0 | 2 |
| 后端状态校验 | 0 | 0 | 2490611 | 40156 | 2 | 4 |

可信库字段呈现指敏感值在可信最小化模块输入中的呈现，不能和对话 Agent 多读字段直接相加来制造同口径优劣。24 次总模型调用上限包括最小化，统一每次输出上限 256；有限预算也可能使最小化推理截断。预算公平不意味着原算法在充足预算下只能达到这个结果。若要对原方法作强胜负主张，还需要最小化预算敏感性检查。

完整保留的 HTTP 尝试 **7116** 次；错误状态计数 `{"429": 513}`；中断记录 0。成功返回在工具执行前落盘，恢复时重放而不重新生成；审计中未完成轨迹的已成功返回数为 0。网络超时的提供方计算与账单仍不可精确推断。

逐步重放通过：**648 条轨迹、6603 次模型输入**。失败轨迹 0 条，逐条指标见 `additional-analysis.json`。

## 能证明与不能证明

- 可比较当前动态任务中实际路径必要性与事前相关性筛选的区别，及其模型/工具/确认开销。
- B/C 的配对结果才用于判断强制状态校验是否在本轮带来额外收益；A/C 同时改变可信最小化和升级流程，不能只归因于单一组件。
- 单次未泄露不等于通用安全保证，实际零多读也不说明所有模型和更强攻击都会遵守。
- 未验证真实用户批准体验、现实服务集成、自动授权规则提取、部分值或隐藏思考泄露、跨模型泛化。
- 后续若要提升攻击强度，应在独立开发集设计攻击，重新冻结后再测新任务；不能在这批正式题上反复调攻击后当作盲测。
