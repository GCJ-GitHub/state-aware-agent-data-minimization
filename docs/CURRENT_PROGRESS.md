## 1. 当前处于什么阶段

已经形成**可运行、可复核的研究原型**：从基础工具契约与可信证据推导当前步骤的数据需求，在交付时重验证，并给出可恢复反馈，让 Agent 自己继续调用工具。

## 2. 最新新任务结果：应优先引用这一批

同一 MaaS `qwen3.8-flash`，120 个参数化合成任务、60 对状态配对，单分支/中途换分支/多阶段各 40 题。三组各重复 3 次，合计 1,080 次尝试；规则、原生工具接口、授权、确认、恢复和预算在运行前冻结。重复种子不视为额外独立任务。

| 方案 | 业务完成 | 原值字段累计 | 最终未用字段 | 证据过期字段 | 工具调用 | 模型调用 | 模拟确认 | 可见文字泄露轨迹 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 事前给齐 | 359/360 | 1752 | 1049 | 1 | 2775 | 3134 | 139 | 1 |
| 自行按需 | 359/360 | 850 | 144 | 144 | 3487 | 3840 | 141 | 0 |
| 后端按状态校验 | 359/360 | 707 | 0 | 0 | 3446 | 3806 | 141 | 1 |

字段累计按每条尝试内去重再相加，不是不同真实用户数。最终未用、过期交付、提前读取和最终回答泄露是不同指标，不能合并当作同一件事。

### 能说明什么

- 后端组相对自行按需，模型接触的原值字段 850→707，少 143（16.8%）；最终未用字段 144→0。
- 主要增量来自状态变化：自行按需组过期字段 144，后端组 0。后端实际拦截 120 次，119 条拦截轨迹完成任务。
- 业务完成均为 359/360（99.7%），但不是每题都成功；三组失败任务也不是同一条。原值总量受不同失败路径影响，所以不把 143 个差额全部当作同质隐私事件。
- 工具调用少 41 次，模型调用少 34 次，确认均 141 次。但配对区间跨过零，因此**没有证据支持稳定的调用效率优势**。
- 单分支和多阶段静态任务中，自行按需已没有最终未用字段；不能宣称后端在每类任务里都额外少读。

以 60 个状态对为聚类单位、保留同对两个成员与三个种子，5,000 次 bootstrap：后端减自行按需的最终未用字段均值差为 -0.400/次，95% 区间 [-0.550, -0.258]；工具均值差 -0.114/次，区间 [-0.617, 0.372]；业务完成率差为 0，区间约 [-0.833, 0.833] 个百分点。区间仅条件于当前合成任务设计，不是生产分布保证。

### 不能掩盖的限制

1. 后端组仍有 1 次最终回答泄露合法已读字段；事前组也有 1 次，自行按需组为 0。少读不等于端到端零泄露，不能从这批稀疏事件断言真实泄露率优劣。
2. 若另要求正常最终文字收尾，三组分别为 354/360、352/360、355/360。这是补充诊断，不替换事前冻结的业务完成终点。
3. 事前组动态事件实际触发 108/120，另两组均 120/120。事前组有少数复用值跳过触发步骤；其动态子集并非完全相同的外部状态暴露，不能把三组全部差额归因于单一放行时机。
4. 有 1 条 HTTP 400 中断：已完成业务但没有正常收尾，仅离线重建 25 次真实缓存回复，没有伪造模型回复或补执行。另有 1 条 HTTP 429 中断按原请求从缓存继续。
5. 14,392 次 HTTP 尝试包含 3,555 次 429、1 次 400 和初始受限网络产生的 56 次无状态错误。重试不是模型返回，提供方超时计算/费用无法精确还原。
6. 独立检查发现一条已经失败的自行按需轨迹重复身份核验两次；没有重复终端业务效果。检查器原先把前置重复也一概禁止，修正后单列该行为，主计分器、任务和冻结源码未改。

## 4. 更早的本地与多模型结果仍保留

2026-11-19 的完整跨模型实验使用 120 题、三组、三个种子、两个模型，共 2,160 条完成轨迹：

| 模型 | 事前给齐成功 | 自行按需成功 | 后端校验成功 | 解读 |
|---|---:|---:|---:|---|
| 本地 Qwen3-1.7B-4bit | 339/360 | 268/360 | 268/360 | 少读存在明显效用代价，不能宣称所有模型都无损 |
| MaaS qwen3.8-flash | 360/360 | 360/360 | 360/360 | 当时自行按需已零多读，校验未触发；不能用它证明强制校验的额外收益 |

这与新状态证据实验不矛盾：旧题的普通流程没有激活同一类旧理由问题。新题用新的状态变化压力来测试读取理由是否仍成立，不能把新结果倒写成旧实验已经证明。

更早四 MaaS 模型在28道状态切换诱导题上各56轨迹：四者最终应答/应拒均14/14；Qwen可见推理泄露6/28→0/28，其他模型未观察到进一步可见推理收益，GPT无可读推理。它们的服务预算不同，不能与本地推理预算或当前工具题直接混比。详情见 [四模型报告](../MAAS-FOUR-MODELS.md)。

物流、退款、AirGapAgent-R、恢复规则开发和留出验证均保留在[历史索引](EXPERIMENTS.md)，没有把旧失败、无收益或混杂实验删掉。

## 6. 实现与设想的分界

| 事项 | 当前状态 |
|---|---|
| 当前步骤字段与证据版本约束 | 已有代码与自主模型轨迹 |
| 拒绝后模型自主恢复 | 已有代码与轨迹，最新120次中119次完成 |
| 多合法计划、用户效用和共享依赖 | 已有结构化原型和机械/合成任务验证 |
| 通用自然语言授权编译 | 尚未验证；关键对照依赖人工核验规则 |
| 自动理解任意API契约 | 尚未实现，契约由开发者维护 |
| 全程句柄替代原值 | 重要替代设计，尚未完成对照 |
| 通用粒度、接收方和输出约束 | 设计方向，不能把图里的模块当作已完成能力 |
| 已有副作用后的跨计划续接/并发原子性 | 尚未完整实现 |
| 真实服务、真实用户体验、开放Web/文件泛化 | 尚未验证 |
| 自动学习新权限/端到端零泄露 | 不属于已证明结论；普通反馈不得扩权 |

## 7. 论文准备度与下一步验证

**现有证据足以支撑一篇系统论文初稿。完整论文还需要回答一个问题：相比每次读取前刷新状态、再按当前路线查字段表的后端，我们的方法多解决了什么？**

最适合写入论文的贡献，是从用户目标、工具依赖和可信状态推导当前步骤的取数理由，在原值交付前重新核对，并在理由失效后让 Agent 自己继续。比如钱包恢复后，银行仍可用，但已不符合用户设定的优先顺序，原先读取账户资料的理由随之失效。

最新的 120 个合成任务共运行 1,080 次。相对模型自行按需，后端将过期依据下交付的字段从 144 降到 0，120 次拦截后有 119 条任务完成，两组业务完成均为 359/360。静态任务里，自行按需已没有最终未用字段。调用差异区间跨零，后端组仍有一次把合法已读字段写进最终回答。现有证据支持动态任务中的取数约束及恢复，调用效率和输出隐私优势仍待验证。[完整实验报告](../necessity-three-arm-holdout/REPORT.md)

AirGapAgent 已有任务级筛选和用户升级，CaMeL 已有工具侧策略和能力约束。论文需要具体说明，从契约推导步骤需求并在状态变化后恢复，在哪些工作流有额外价值。[AirGapAgent §4](https://arxiv.org/html/2405.05175v2#S4) · [CaMeL](https://arxiv.org/html/2503.18813v2)

### 优先验证强基线

1. **先把两个方法写成可执行的方案。** 基线在每次读取前刷新可信状态，校验当前路线和前置步骤，按维护好的字段表放行。我们的方法从工具契约推导步骤需求并在交付时重验理由。两组使用相同模型、授权、确认、恢复反馈与预算。环境在预定业务阶段触发状态变化，两组在同一业务阶段面对同一变化，触发与是否调用取数工具无关。
2. **先手工走通三个案例。** 首选路线恢复时，检查两组是否都拦住旧分支的读取。换路线后仍可复用身份核验时，检查是否能保留满足资源、用途和版本要求的产物并完成任务。用户确实要求精确原值时，检查两组能否按原授权交付，避免误拒。跨计划复用是待完善的设计，这一案例先用来明确规则。
3. **再根据案例差异决定要测什么。** 对比过期交付、误拒、业务完成、重复核验和调用开销。如果两组在既知路线表现相当，重点验证新增流程组合时能否复用现有契约，以及各组分别要新增或修改多少规则。记录字段表的维护工作，也记录工具契约的编写与验证成本。贡献范围按对照结果确定。
