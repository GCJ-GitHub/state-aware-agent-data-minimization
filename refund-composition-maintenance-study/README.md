# 新契约与强路线表的组合退款维护实验

两组在同一份合成退款模拟器中，沿用交付前的当前路线校验、银行授权撤回版本、字段版本、字段权限和一次性退款提交。新契约使用已验证的窄绑定实现。强路线表允许组合路径和共享核验规则。两组用脚本复放工具调用，固定业务轨迹，未计模型或人工维护成本。

| 新规则 | 作用范围 | 合成依赖 |
| --- | --- | --- |
| R1 加强核验 | 钱包及银行；加强模式或大额退款触发 | 同一笔退款只执行一次核验，即使两项条件同时成立 |
| R2 收款人核验 | 银行；收款资料最近变更 | 同时触发 R1 时先完成 R1 |
| R3 大额复核 | 钱包及银行；大额退款 | 等待 R1，若 R2 生效也等待 R2 |

两组共享三条人工编写的配置及同一套预先实现的规则展开器。手工配置的计数是与加规则前的结构化差异，既有迁移代码和编译器工时单独留作范围限制。两个执行器分别使用组合路线表与契约注册表，编译器为两组生成相同的条件化操作，路线表还将其中的路线和步骤展开为配方。生成条目多少取决于当前编译策略。

## 正确性和配置量

矩阵是 4 类路线状态 × 8 个触发条件组合 × 8 个新增字段授权组合，共 256 个用例。独立于编译器的业务判分核对最终退款路线、前置核验顺序、原值字段集合和批准次数。字段未授权且无法走其他合法路线时，安全停止计为正确。

| 指标 | 交付前刷新的强路线表 | 新契约 |
| --- | ---: | ---: |
| 正确流程 | 256/256 | 256/256 |
| 正确提交退款 | 88 | 88 |
| 正确停止 | 168 | 168 |
| 发生多放字段的用例 | 0 | 0 |
| 新增人工规则声明 | 3 | 3 |
| 其中目标引用 / 依赖引用 | 5 / 3 | 5 / 3 |
| 改动已有人工配方或操作声明 | 0 | 0 |
| 生成的操作数，变更前后 | 2 → 31 | 2 → 31 |
| 生成的路线配方数，变更前后 | 2 → 12 | 0 → 0 |
| 原有流程前后完全一致 | 32/32 | 32/32 |

按规则的目标和依赖，银行可用且钱包不可用、只有钱包、两者可用并优先钱包三类旧流程都应重验。另保留无路线的停止流程作为共同校验。每类在新增规则均未触发时，覆盖 8 种字段授权组合，形成 32 条前后回归。影响范围对两组相同。

## 日志和误配置

使用同一份结构化日志记录请求及当前计划、当前状态、规则 ID、已完成与所需的核验、银行授权代数、字段版本、请求和放行的字段名。日志不保存原值。独立重建程序仅从日志的证据字段重建判定，再对照执行器的实际决定。

| 核验项 | 强路线表 | 新契约 |
| --- | ---: | ---: |
| 从证据重建判定 | 7/7 | 7/7 |
| 预期拒绝中没有交付原值 | 5/5 | 5/5 |
| 已知误配置被回归发现并定位到配置差异 | 3/3 | 3/3 |

7 个审计实例覆盖普通放行、组合核验后放行、路线切换、授权撤回再授、字段版本变化、字段超范围和所需前置失效。三处对称误配置是漏收款人规则、复核绑定错字段、共享核验漏掉钱包路线。两组分别有 16、44、64 个用例出现业务结果或字段差异。配置差分识别错误声明的位置，实际轨迹提供可复现反例。这样能检查批准规则与实际部署的分歧。仅有执行日志时，仍需批准规则才能判断某项部署是否写错。

在这套共享编译设施下，契约组少维护一种派生路线表示，人工规则量、旧流程重验范围和结构化日志归因均持平。尚未测开发者用时、自然误配置或人工排障速度。
