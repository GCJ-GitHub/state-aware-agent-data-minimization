# 缩小退款契约的版本绑定范围

本轮同步重跑三组。分别是交付前刷新状态的强路线表、绑定整个计划支持证据版本的原契约、缩小绑定范围的新契约。沿用冻结的五种退款轨迹和三个种子，每组 15 次，共 45 次。模型、任务、状态时序、字段版本、确认、反馈、工具和成功判分与上一轮相同。模型为 MaaS Qwen4-Max，退款为模拟操作，成功以正确的一次业务提交为准。

新契约在签发银行读取时记录银行授权代数。交付前仍核对当前路线与步骤是否适用、原银行授权是否撤回过、精确请求字段的版本是否变化。资源、动作、请求字段集合和单次消费依旧由已有授权验证器校验。钱包可用性用于决定当前路线，其历史版本不参与旧授权的失效判定。实验实现放在本轮模块，原后端和上一轮冻结输入保留，用于同批对照。

当银行仍有授权、银行引用保持不变且当前再次选择银行时，原有读取授权可以复用。撤回后重授和字段更新仍需要重新取数。钱包仍为当前路线时，银行读取仍会被拒。原契约与强路线表继续按上一轮规则运行。

## 复跑

```bash
shasum -c FREEZE.sha256
python run.py --verify
python run.py --workers 3
python summarize.py > summary.json
```

模型网关地址和凭证分别从 `GAIA_MAAS_URL` 和 `GAIA_MAAS_DEV_KEY` 读取。预检直接调用新契约验证器覆盖五种状态变化，并对三组的全部 15 个场景组合做机械复放。两种正式恢复口径为所有运行以及同场景、同种子、三组均达到旧授权判定的匹配运行。

## 实测

45/45 次完成，15 个同场景同种子三组匹配均达到第一次旧授权的交付判定，没有网关中断。

| 指标 | 强路线表 | 原契约 | 新契约 |
| --- | ---: | ---: | ---: |
| 正确退款 | 15/15 | 15/15 | 15/15 |
| 误放行 | 0/9 | 0/9 | 0/9 |
| 误拒绝 | 0/6 | 3/6 | 0/6 |
| 正常复用旧授权 | 6 | 3 | 6 |
| 重新准备读取 | 9 | 12 | 9 |
| 旧请求判定后工具调用 | 66 | 78 | 66 |
| 全程工具调用 | 126 | 138 | 126 |

新契约消除了临时切到钱包再切回银行的三个误拒绝。对应三次运行每次少四步，分别是重新查状态、重选计划、重新准备和重新取数。授权撤回重授、银行引用改变、钱包仍为当前路线的九次均拒绝旧授权，并全部恢复完成。无关备注变化与银行授权始终有效的往返，两个场景的六次都复用了旧授权。

新契约和强路线表在 15 个逐对结果上的复用判定、正确退款与交付后调用次数均一致。结果支持缩小依赖绑定范围能消除原契约在这些冻结轨迹里的额外恢复。新契约与强路线表在当前任务上的实际效果持平，改动范围限于本研究的模拟后端。这批复跑使用原有合成轨迹。
