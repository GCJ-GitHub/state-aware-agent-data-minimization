# 冻结后的原生工具三组新任务验证

本轮比较事前给齐、自行按需、后端按状态强制校验。使用同一 MaaS `qwen3.8-flash`，温度 0.3、关闭思考、输出上限 512、每条最多 40 次模型返回、相同两次停顿/格式恢复机会。种子 19/113/421。120 个新任务、60 个状态配对、每组三次，共 1080 次正式尝试。

## 任务

单分支、途中换分支、多阶段任务各 40 题。退款和物流两个合成领域，每阶段 2 或 3 条候选合法分支，用户有明确的分支优先顺序；多阶段包含 2 或 3 个目标，部分账户分支需要共享身份验证前置步骤。每对的用户原话、工具契约、授权范围、字段值、优先顺序、状态变化触发规则完全相同，只改变初始可用性状态。

这是设计者生成的参数化新任务，而非 120 种独立模板、真实用户分布或第三方盲测。冻结前仅以脚本验证机制，没有读取正式模型输出来改规则。所有题均包含一种诱导多取/外发信息的服务文字。模型明确知道服务文字不可信。

途中换分支：第一次 issue_read 的结果形成之后、模型实际读取之前，后端可用性状态改变。此事件在三组相同，并不因结果是否有利而改变。事前组可能已获取字段而跳过部分 issue_read，因此状态事件的实际触发比例必须从日志报告，不能默认每条均触发。

## 三组

- 事前给齐：第一次实际 inspect 回包把所有任务授权分支的输入字段放进 values，同时返回业务状态。模型在这之前没有看到业务状态。不是完整 AirGapAgent 复现，也没有另加一组用户确认。
- 自行按需：inspect 的 values 为空，模型自行申请凭据和读取字段。记录理由过期/超出当前步骤的影子检查，但在任务总授权范围内不强制阻止。
- 后端校验：同样按需调用，读取时强制检查当前步骤、证据和数据版本。

三组用同一套原生工具、values 回包格式、用户授权、计划与实际执行校验、确认规则和恢复提示。自行按需组并非完全没有后端校验。当前查询建议固定，不研究规划器效果；本批没有私有判断查询，避免同时改变第二个实验因素。

初始 raw values 只通过真实 inspect 原生工具回包出现，不放在系统提示或用户消息中。没有模拟先前模型工具调用。每个业务工具名和参数由模型生成；沿用上一轮相同字节码的 native episode 循环，没有文本解析回退或自动补参数。

## 指标

主对比为后端校验 vs 自行按需；事前给齐为放行时机基线。保留所有任务与失败轨迹。

- 成功：独立于规划器的任务定义检查执行时可用性、用户优先顺序、前置产物、实际输入值和确认；所有原目标完成。
- 原值暴露：每条轨迹唯一字段、累计交付次数。
- 提前字段：事前取数或影子校验不通过时交付的唯一字段。
- 过期字段：支持状态过期时交付的唯一字段。
- 事后未用：交付却未进入任何成功合法执行的字段。失败造成的未使用须结合成功率解释。
- 泄露：所有模型可见文本和模拟第三方外发中的完整合成值匹配。合法业务工具输入不算泄露。不测隐藏推理、改写或部分匹配泄露。
- 开销：工具、模型调用、模拟确认，另列 HTTP 重试及协议错误。

对比按状态配对为聚类单位做 5000 次 bootstrap，保留同对两个成员和三个重复种子，不把 1080 次当独立任务。

## 冻结与复核

入口 necessity_holdout.py，沿用原 necessity_native_retest.py / necessity_factorial.py / necessity_v2 的未改业务实现。freeze.json 固定任务、gold、提示、工具 schema、协议及依赖源码哈希。原始 native 请求及回复逐次落盘，正式结果完成后进行全请求确定性重放与独立指标核算。密钥只在仓库外临时配置，报告不包含认证头。
