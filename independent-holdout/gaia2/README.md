# Gaia2 Adaptability 三组先导实验

本实验使用两道同为原生订单取消的公开任务。0603 要求取消后按原价重下，0863 要求取消后换商品。两题都由上游定义用户请求、原始应用数据、取消事件、相对触发时间和正确操作。保留原始 JSON、原生应用工具以及 Gaia2 在线事件图判分。上游的原生判分器用同一个本地 Qwen3-8B 提供语义评判，模型配置与上游默认配置可能不同。 [原始任务](https://huggingface.co/datasets/meta-agents-research-environments/gaia2/tree/c128283/adaptability) · [原生判分说明](https://facebookresearch.github.io/meta-agents-research-environments/foundations/scenarios.html)

## 冻结与对照

[protocol.json](protocol.json) 记录数据文件 SHA-256、上游运行器提交、样本、种子和字段规则。[FREEZE.sha256](FREEZE.sha256) 绑定正式运行入口和规则。初次启动时，模型返回了完整的 JSON 工具调用，原生动作解析器要求额外的 `Action:` 前缀。预跑还遇到了单条回复内含多个动作的问题。本地接口接入了单个 JSON 动作的结构化输出约束，并继续兼容完整 JSON 缺少前缀的情况。三组使用同一格式适配，模型仍提供完整的工具名和参数。之后识别出本地接入漏转了 Gaia2 内部的工具回包消息角色，从而丢失观察。隔离这次接入错误产生的诊断行，并复用原生 LiteLLM 角色映射，验证模型可见真实回包后从头运行。字段规则保持原哈希。

| 组 | 在这两题的实现 |
| --- | --- |
| Agent 自行按需 | 接收原工具结果，自行决定下一次读取。 |
| 读前刷新路线表 | 进入工具时读原生事件日志，使用当前路线对应的字段规则。 |
| 契约后端 | 按读取时的业务阶段绑定用途与版本，在返回工具结果时复查版本并剔除失效字段。 |

三组共享原生模型接入、提示、工具入口、业务写操作、授权语义和预算。业务条件来自原生的取消事件。三组按题和种子配对，轮换执行顺序。每次最多 36 次模型响应，每次推理折合相同的 1 秒模拟时间，环境事件保留上游的 1 秒相对延迟。正式本地权重 SHA-256 为 `a3de86cd1c132c822487ededd47a324c50491393e6565cd14bafa40d0b8e686f`，两题都使用 Ollama 的 `qwen3:8b`。任务数据留在本机模型和本机模拟工具内。

字段评分由本研究加在模型工具回包边界。每次运行只计取消已发生后新交付的被追踪字段，重复读取同一字段在同次运行内去重。原工具允许查历史订单并保留其结果。原生判分器独立判定业务成功。模型视野中的旧记忆、最终答复泄露和所有应用的所有字段均超出这轮评分范围。

恢复工具开销使用切换后的工具调用数，并单独统计被拒之后的调用及其最终判分。各组匹配对只包含两组均发生取消的同题同种子运行。自然发生的跨事件读取可以在记录中核查，没有人为注入网络延迟或改变业务事件触发。

## 复跑

在上游运行器对应提交安装依赖，准备本地模型和被冻结的 Parquet 后运行以下命令。只有工具名、阶段和计数进入结果文件。

```bash
shasum -c FREEZE.sha256
LITELLM_LOCAL_MODEL_COST_MAP=True python run.py --parquet /path/to/adaptability.parquet --output results.jsonl
python summarize.py results.jsonl
```

## 实测结果

正式矩阵完成 18/18 次。按同题同种子核对，三组在六个配对上的工具名序列都相同。

| 组 | Gaia2 成功 | 触发原生取消 | 切换后的多读字段与恢复调用 | 工具调用合计 |
| --- | ---: | ---: | --- | ---: |
| Agent 自行按需 | 0/6 | 0/6 | 无可计分运行 | 169 |
| 读前刷新路线表 | 0/6 | 0/6 | 无可计分运行 | 169 |
| 契约后端 | 0/6 | 0/6 | 无可计分运行 | 169 |

每组共有 169 次模型响应和 169 次工具调用，平均每次运行 28.17 次工具调用。匹配的切换后比较分母为零。日志中的多读与拒绝原始计数均为零，因为没有走到政策发挥作用的阶段。

- **0863 换货。** 九次都耗尽 36 次模型响应预算。轨迹只出现产品搜索和加购物车。原生工具多次返回商品不存在，所有运行都没到结账和用户汇报。
- **0603 原价重下。** 每组种子 19 和 421 分别用了 21 和 4 次工具调用，在首次结账、邮件均未完成时就调用了用户汇报；上游没有触发取消。种子 113 各用完 36 次响应，主要重复搜索。三组全程没有执行到需调用语义裁判的判分步骤。
- 两个案例的上游 Oracle 轨迹都成功复放出原始取消事件。正式运行的本地接入通过了独立的回包可见性测试。运行器记录过未被任务访问的演示文件系统路径警告，任务轨迹中没有文件系统调用。

这组结果说明当前本地模型和工具接入能完成对照运行，但模型始终卡在前半段，尚未验证后端是否能在 Gaia2 的原生流程里减少多读或改变恢复开销。后续若更换模型，应先用与这两道正式题分开的 Gaia2 开发题检查模型能否稳定到达上游状态切换。确认可达后再冻结并执行正式矩阵。
