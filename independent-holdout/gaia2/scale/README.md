# Gaia2 Adaptability 全量覆盖与三组字段对照

数据固定为 Gaia2 Adaptability validation 的原生快照，包含 160 道公开题和 380 个作者定义的环境事件。任务、工具、事件依赖与 Gaia2 业务判分器沿用上游。模型使用固定的 36 次响应预算及相同的模拟推理时间。Qwen4-Max 由 MaaS 提供，正式对照的语义裁判也使用 Qwen4-Max。外发内容为公开场景运行期间模型实际可见的提示、工具回包和上游判分提示。

| 运行 | 任务 | 计划运行数 | 指标 |
| --- | --- | ---: | --- |
| Qwen4-Max 三组 | 0603、0863，两道已有预先冻结的字段规则的题 | 18 | 业务成功、状态切换、切换后多读、拒绝后恢复和调用数 |
| Qwen4-Max 全量 | 160 道题，每题三个种子，Agent 自行按需 | 480 | 样本覆盖、原生事件达到率、业务成功和调用数 |
| 本地 Qwen3-8B 预检 | 0913、0924，与已完成的 Qwen4-Max 开发题预检同题同种子 | 4 | 原生状态切换、业务成功和调用数 |

`coverage.json` 包含 160 道题的环境事件类型和字段规则覆盖情况。只有两道题具备已冻结字段规则，全量表只用于任务能力与状态切换覆盖。字段规则空白或未发生切换时返回空值，表示该运行无法计算切换后多读。开发题也计入全量描述性覆盖，单独的预检用于确定本地模型是否具备进入三组对照的条件。全量记录的是这个模型接入和预算下的表现，不能用来估计所有 160 道题的后端收益。

Qwen4-Max 三组和全量模式读取 `GAIA_MAAS_URL` 和 `GAIA_MAAS_DEV_KEY`。可以用同一路径继续未完成的任务，运行键为题号、组别、种子，无需覆盖已生成的记录。以下命令读取实时记录并拒绝重复的运行键。

```bash
shasum -c FREEZE.sha256
python status.py
```

## 全量原生事件复放

Oracle 审计使用上游提供的正确写操作机械复放，不消耗模型调用。160 道题全部复放成功，380/380 个原生环境事件均以原 ID 命中。这个结果确认数据快照和原生事件可以复现。自主 Agent 的成功率以实跑记录为准。

本地开发题预检已完成。同题同种子的 Qwen3-8B 有 2/4 次触发原生事件，0/4 次通过完整业务判分。触发的两次均来自 0924。该接入没有达到预先定义的 4/4 稳定切换门槛，本地模型保留为小规模预检结果。

初次并发同时启动正式和全量队列，MaaS 返回限流。保留已完成记录，降低并发，按先正式后全量的顺序续跑。限流不计入场景工具调用。

18/18 次完成，无未恢复的网关或运行错误。按运行业务成功率，三组均为 2/6。三组合计有 7 次触发原生取消。

## 全量自主实测

完整 Adaptability validation 的 160 道题均完成三次分派，共 480 次。下面的全量结果使用 Qwen4-Max 自行按需组。

| 口径 | 完整任务通过 | 至少触发一个原生事件 | 触发该题全部原生事件 | 未判分的连接中断 |
| --- | ---: | ---: | ---: | ---: |
| 首跑分派 | 170/480 | 342/480 | 318/480 | 5 |
| 补齐连接中断 | 173/480 | 347/480 | 323/480 | 0 |

五次连接中断集中出现于第三个种子。只补跑这五个原题、原种子，全部恢复评测，其中三次通过。原始运行逐条保留，补跑单列。补齐后各随机种子成功 57/160、59/160、57/160。160 道题中有 88 道至少成功过一次，141 道至少触发过一次原生事件。补齐后的全量共有 7347 次业务工具调用，平均 15.31 次/运行。先后调整工作线程以应对限流和检查点续跑，模型、任务及评分规则保持相同。运行级指标在场景预算和此接入下成立。

全量覆盖结果可用于判断能否进入原始状态切换。后端收益仍以冻结的两道题、18 次三组对照为准。该对照仅有一组同题同种子三组均触发切换，观察到的后端拒绝数为零，因此没有拒绝后成本样本。
