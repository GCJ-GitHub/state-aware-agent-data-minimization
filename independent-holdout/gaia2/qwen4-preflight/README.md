# Gaia2 开发题预检 · Qwen4-Max

这轮检验模型能否完成原生流程的前半段，触发原生状态变更，再完成变更后的业务步骤。使用公开开发题 0913（订单取消后改买足球气球）和 0924（取消后改买另一款手办），每题各跑种子 19 和 113，只跑 Agent 自行按需。上轮两道题未重新运行。部署用 MaaS `qwen4-max`，语义裁判也使用同一个模型，沿用 Gaia2 的原生判分器和触发条件。三组正式对照和字段规则继续保存在上级目录。

运行器复用原生工具、消息角色转换、工具调用前缀适配和三十六次响应预算。MaaS 端使用 JSON 模式让模型每次输出一个动作。工具名和参数均由模型给出。预检使用公开任务，环境状态留在本机，模型只接收它能看到的提示和工具回包。上游判分器需要语义判断时也将对应判分提示送入同一模型。日志只记录工具名称、调用次数、阶段和 HTTP 状态。

协议和运行入口在执行前已固定。预检标准为两题的两次重复均触发原生取消。业务成功分开报告。该预检记录不计入三组正式对照，也不能用来单独估计更换模型的因果效果。

## 复跑

配置 `GAIA_MAAS_URL` 和 `GAIA_MAAS_DEV_KEY` 环境变量后，从本目录运行以下命令。

```bash
shasum -c FREEZE.sha256
LITELLM_LOCAL_MODEL_COST_MAP=True python run.py \
  --parquet /path/to/adaptability.parquet --output results.jsonl
```

## 结果

| 开发题 | 触发原生取消 | Gaia2 判分通过 | 每次总工具调用 | 每次切换后工具调用 |
| --- | ---: | ---: | ---: | ---: |
| 0913 气球换款 | 2/2 | 2/2 | 13、13 | 8、8 |
| 0924 手办换款 | 2/2 | 2/2 | 15、15 | 8、8 |
| 合计 | 4/4 | 4/4 | 56 次 | 32 次 |

两道题都在两次重复中通过预定的状态切换门槛。四次运行的初始订单、原生取消和后续换款均通过原生判分。MaaS 请求均返回 HTTP 200。当前数据只支持可达性结论，可以用这套接入开展后续三组对照。由于题目、模型与接入均与上一轮不同，这里不估计模型提升幅度。切换后的 8 次调用是基础业务开销，后端拒绝后的额外恢复开销需在三组对照中测量。
