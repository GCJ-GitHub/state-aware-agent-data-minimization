# 交付前刷新路线表与契约后端

沿用上一轮 Gaia2 交付窗口测试的三道任务和三个种子。两组同步重跑，共 18 次。模型为 MaaS Qwen4-Max，原始任务、原生取消事件、业务判分器、请求与交付位置、反馈文字及推理预算相同。原始题和模型请求保持原生交互，辅助读取和交付窗口由实验框架统一安排。

| 组别 | 交付前的判定 |
| --- | --- |
| 交付前刷新路线表 | 重新读取原生状态，按当前路线表检查商品目录 ID 是否仍允许交付。取消后，当前路线已切换到换货，旧 ID 不在允许字段内。 |
| 契约后端 | 比对请求时绑定的版本与交付时的版本。这批任务的原生取消使版本发生变化，旧请求在交付时失效。 |

两组均使用原有的读前合法性检查。拒绝时返回相同提示，Agent 仍由自己继续调用原生工具。这里的单次取消使两种判定产生同一个回复，测试可回答这一窗口下的拦截、任务成功与恢复调用是否还有差别。

统计分别使用所有分派和配对分母。配对要求同题同种子且两组均把回包或明确拒绝送到模型。统计的是挂起回包带来的旧值交付。公共辅助读取单列，工具调用包括业务动作和模型自行发起的状态查询。判定耗时、已在上下文中的旧值和更复杂的版本变化均不在本轮指标范围。

## 复跑

```bash
shasum -c FREEZE.sha256
LITELLM_LOCAL_MODEL_COST_MAP=True python run.py --parquet /path/to/adaptability.parquet --output results.jsonl --workers 3
python summarize.py > summary.json
```

模型网关地址和凭证分别从 `GAIA_MAAS_URL` 和 `GAIA_MAAS_DEV_KEY` 读取。

## 结果

18/18 次正式运行完成，无网关或运行中断。两组共 17 次命中交付窗口并将拒绝送到模型。这 17 次均无过期原值交付。

| 组 | 全量业务成功 | 命中交付窗口 | 旧值交付 | 拒绝后业务通过 |
| --- | ---: | ---: | ---: | ---: |
| 交付前刷新路线表 | 8/9 | 8/9 | 0/8 | 8/8 |
| 契约后端 | 6/9 | 9/9 | 0/9 | 6/9 |

8 个同题同种子的配对中，两组均命中交付窗口和拦截了原值。路线表成功 8/8，契约组成功 6/8。切换后原生工具调用合计为 59 和 58 次，平均 7.375 和 7.250 次，契约组相差 −0.125 次。在两组均成功的 6 对里，调用合计为 43 和 42 次。配对的全程模型响应合计为 134 和 158 次，模型响应开销包含切换前的响应。

两个配对中的契约组失败都出现在 0913（种子 113、421）。模型做完重下单和通知后在 36 次响应预算处停止，未完成最后的用户汇报。0863 种子 421 未进入配对：路线表运行未触发原生取消，契约组拦住了旧值，随后也在完成最终汇报前耗尽了响应预算。该案保留在全量分母。

这批任务的两种交付判定给模型的拒绝文字相同。实验结果支持交付前校验能拦截这类过期回包，也显示工具调用量接近。当前小样本观察到的任务通过差异无法归因到表查询或版本比对本身。业务条件反复切换时的授权复用，以及维护和审计成本，属于不同的评估问题。
